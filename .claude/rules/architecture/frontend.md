# Window (React + iro-ui)

The window shows what Rust sends and passes clicks on. It doesn't decide, compute, parse or touch files.

- Every call to Rust is a function in `src/lib/backend.ts`; nothing else imports `@tauri-apps/*`.
- `backend.ts` answers with fake data when `!("__TAURI_INTERNALS__" in window)`, so `pnpm dev` previews every view.
  The data, its helpers and the fake job live in `src/lib/fakeData.ts` (a long simulation gets its own file, as
  `fakeHunt.ts`); the state the fake answers change stays in `backend.ts`, starting from `fakeData.ts`'s `…AtStart`
  values. Name preview states with URL flags (`?setup`, `?empty`) and list them in `fakeData.ts`'s header comment.
  Window controls (minimize, maximize, close, the maximized state) are `backend.ts` functions too.
- Types come from `src/lib/types/` (generated by ts-rs; never edit them). Don't redeclare a Rust type in TypeScript.
- Sorting, filtering and counting a list Rust sent is fine for display. Anything that changes data, or that Rust needs
  to agree on, is a command.
- Build from iro-ui components (Tabs, DataTable, Dialog, EmptyState, ProgressBar…). App CSS goes in `src/styles.css`
  or the view's own `.css`, using `--iro-*` tokens only, never raw colors or sizes.
- Accessibility: every control has a label, keyboard use works, and color is never the only signal (type colors in
  lists also carry a label or icon).
- Every view works from the smallest window (820 × 560, `src-tauri/src/window.rs`) up to a wide screen: check a
  changed view at both in `pnpm dev`. Under 960px the header turns compact (`styles.css`).
- Tooltips are iro-ui's `Tooltip` (an `IconButton`'s label already is one). Never a `title` attribute.
- It's a desktop window: text keeps the arrow cursor and can't be selected, and pictures can't be dragged, so a press
  on a card's picture that moves still clicks the card (`styles.css`). Only typed fields show the
  text cursor. Mark text worth copying (a saved file's path, an error) with the `selectable` class.
- The browser's own right-click menu is off (`App.tsx`), except in text fields and `selectable` text. A row the user
  acts on (a file, a download, a site) gets an iro-ui `ContextMenu` with the same actions as its buttons;
  `src/components/fileMenu.tsx` has a library file's (Open, Show in folder) and Copy link.

## Layout

- `src/main.tsx`: the iro-ui style import, `IroRoot`, `Toaster`. Nothing else.
- `src/app/`: `App.tsx` (the header: name, the view tabs centered, the Downloads and Settings buttons; the first-run
  screen until there's a library), `AppBackdrop.tsx` (iro-ui's liquid `Backdrop`), `SettingsProvider.tsx` (the settings
  and `useSettings`), `useTools.ts` (tool status, installs and their job events), `useCached.ts` (a value from Rust kept
  for the session), `useThumbnail.ts` (a library file's thumbnail, or a link's), `useHandedPage.ts` (opens Grab with a
  page the extension handed over), `viewShown.ts` (how many times a view has shown), `KeptView.tsx` (an opened view,
  kept hidden), `openView.ts` (a view opening another), `useDownloads.ts` (the Download list and each download's
  progress, which the Download, Downloads and Grab views read), `WindowControls.tsx` and `views.ts` (the tabs, and the
  header's buttons' views). Shared hooks go here too.
- `src/features/setup/`: the first-run screens (`SetupView`, then `ToolsStep`). They aren't tabs, so they're not in
  `views.ts`.
- `src/features/settings/`: Settings in tabs (`SettingsView`'s `TABS`), one component per section, each a card
  (`<Panel as="section" className="settings-section">` with a `SectionTitle`). A new setting goes
  in the section it belongs to; a new section in the tab that fits, or a new tab when none does.
- A view that shows data Rust already sent this session reads it through `useCached` (or keeps its last list, as
  `useTools` and `useDownloads` do), so it opens complete in its first frame instead of shifting as rows arrive.
- Views stay mounted once opened (`App.tsx` hides the others), so fields, results and scroll survive switching. Keep
  a view's state in the view, not in module variables. `KeptView.tsx` hides with `content-visibility: hidden`
  (`styles.css`), which skips the hidden view's layout and costs little on a switch; it keeps the scroll itself.
  Don't hide views with `visibility`, `inert` or `pointer-events`: on a thousand-row view they cost half a second.
  A load that runs on mount puts `useViewShown()` (`src/app/viewShown.ts`) in its effect's dependencies, so it runs
  again each time the view shows; `useCached` does this already.
- Job progress reaches the window only through `onJobProgress` and `onJobFinished` in `backend.ts`; views follow
  their own jobs by id. Events come in bursts (a grab sends one per file): apply them in batches with
  `src/lib/coalesce.ts`, and let a row in a long list read its own download with `useDownload(id)`, so a report
  redraws one row, not the list. Long lists show a page at a time (iro-ui `Pagination`, as the Download list and
  `FindResults` do) or use `content-visibility: auto`. Changes in the library folder arrive through
  `onLibraryChanged` (the Gallery reloads).
- The header is the title bar (ADR-0011): it follows `AppInfo.frame`. `custom` adds `WindowControls`, `custom` and
  `overlay` make it the drag area (`data-tauri-drag-region`), `native` is a plain header.
- `src/features/<view>/`: one folder per view, `<View>View.tsx` plus its own components.
- `src/components/`: components two or more views use; `src/lib/` holds the display helpers they share
  (`format.ts`, `kinds.ts`). `src/components/finds/` is a list of finds to pick from (`FindResults`: filters, sort,
  grid or list, pages), shared by Grab and a mirror's media in Scrape (ADR-0033).

## How to add a view

1. Create `src/features/<view>/<View>View.tsx`.
2. Add it to `MAIN_VIEWS` in `src/app/views.ts` (label and iro-ui icon). The header tabs follow the list.
3. Give its data fake answers in `backend.ts` (the data in `fakeData.ts`) so it previews in `pnpm dev`.

## Updating iro-ui

Change the tag in `package.json` (`github:nyaridev/iro-ui#vX.Y.Z`), run `pnpm install`, and read iro-ui's
`CHANGELOG.md` first. Never install it from a path or a branch.
